# 시장자료 갱신 (2026-11-24부터 매일 아침 전체 갱신)

매출분석도구의 «목표·추이 > 건설동향 / 방화문시장 분석 / 철강시세 전망» 세 화면은
`market_feed.json` 을 받아 화면 자료를 덮어쓴다(index.html 의 `script#v1540-market-feed`).
주간 갱신은 **market_feed.json 만** 고쳐 올린다. index.html·APP_BUILD 는 건드리지 않는다.

## 화면 원본 (2026-11-23~)
- 세 화면(건설동향·방화문시장 분석·철강시세 전망)의 원본은 홈페이지 저장소 bookmark/market.html. 매출분석도구 세 메뉴(v1708)와 홈페이지 탭 화면 모두 이 페이지를 불러옴.
- 자료는 그대로 이 저장소의 market_feed.json 만 고치면 됨(market.html 이 ../sales/market_feed.json 을 받음). HTML 은 건드리지 않음.

## 매일 아침 전체 갱신 (2026-11-24 사용자 요청, 매일 08시 전 — 목요일 주간 갱신을 대신함)

사용자 요청: «매일 오전 8시 건설동향 / 방화문시장 분석 / 철강시세 전망 페이지 신규내용 및 전체 페이지 업데이트». 
그래서 **매일** 아래 «고칠 자료» 전체(철강·환율·건설동향·방화문)와 «매일 아침 갱신» 두 절의 항목을 함께 본다. 목요일 주간 예약 작업은 없앰.

- 범위: 세 화면 전부 — 건설동향(asOf·verify·summary·policy·checkTbl·trend·conWarn·chain·history·srcline 등 MK_DEFAULT 항목), 방화문시장 분석(fd… 항목·fdNews·fdNewsAsOf), 철강시세 전망(st… 항목·stFx·stAsOf).
- 새 자료 기준: 지난 1~3일 기사·공표를 우선 보고, 그 사이 새로 나온 월간 통계(국토교통부 주택통계, 국가데이터처 산업활동동향, 건산연 CBSI·전망, 건설공사비지수 등)가 있으면 해당 항목 전체를 새 숫자로 고친다. 같은 숫자를 매일 다시 쓰지 않는다.
- 신규 내용: 새 사안(제도 변경·고시·입법예고·통계 공표·시세 변동)은 해당 표·뉴스에 줄을 추가하고 `history`(건설·방화문) 또는 `stHistory`(철강) 맨 앞에 `오늘|내용` 한 줄. `hkeys` 날짜도 오늘로.
- 건설동향·방화문 항목을 하나라도 고친 날은 `asOf` 를 오늘로. 철강만 바뀐 날은 `stAsOf` 만. 뉴스를 바꾼 날은 `fdNewsAsOf`.
- `tag`: 오늘 날짜, 이미 오늘 tag 가 있으면 끝 글자를 다음 영문 소문자로.
- 바뀐 숫자·내용이 하나도 없으면 커밋하지 않는다.
- 검사·커밋 순서는 «순서»와 같음. 커밋 메시지 «시장자료 일일 갱신 YYYY-MM-DD — 주요 변동 한 줄».
- 화면 원본은 bookmark/market.html — HTML 은 건드리지 않고 market_feed.json 만 고침.

## 파일 형식

```json
{ "tag": "YYYY-MM-DD", "asOf": "YYYY-MM-DD", "note": "...",
  "hkeys": { "history": "YYYY-MM-DD|", "stHistory": "YYYY-MM-DD|" },
  "update": { "항목": "값", ... } }
```

- `tag` 는 이전보다 커야 화면이 받는다. 같은 날 다시 고치면 `2026-11-26b` 처럼 끝에 영문 소문자 한 자.
- `update` 에 넣은 항목만 바뀌고, 빠진 항목은 화면에 남아 있는 이전 값을 그대로 쓴다.
  지난 주 파일의 항목은 그대로 두고, 새 자료가 있는 항목만 값을 고친다.
- 표 항목은 줄마다 `|` 로 칸을 나눈다. **칸 수를 바꾸지 않는다**(검사 도구가 막음). 줄 추가·삭제는 가능.
- 기간·기준일 같은 좁은 칸은 짧게(stTrade «기간» 30자 이내). 긴 설명은 그 줄의 마지막 설명 칸에.
- 추세 칸은 `상승`·`하락`·`보합` 중 하나만 쓴다(다른 말은 화면에서 «보합»으로 보임).
- `history`·`stHistory` 는 맨 앞에 `날짜|내용` 한 줄만 넣는다(이전 줄은 화면이 알아서 이어 붙임).
- 화면 문구는 개조식(«~함·~임·~음»), «습니다·입니다» 쓰지 않음. 강조는 `<b>…</b>` 만.

## 순서

1. `git pull` 최신 main.
2. `cp market_feed.json /tmp/prev_feed.json`
3. 자료 조사 후 `market_feed.json` 수정(tag·asOf·stAsOf·hkeys 날짜를 이번 주 목요일로).
4. `node tools/market_feed_check.js market_feed.json /tmp/prev_feed.json` → «✓ 검사 통과» 일 때만 다음 단계.
5. 커밋 메시지 «시장자료 주간 갱신 YYYY-MM-DD — 철강·건설 주요 변동 한 줄», main 에 push.
6. 결과 요약: 바뀐 숫자(이전→이번)·못 찾은 항목·출처 목록.

## 매일 아침 갱신 (철강시세·원/달러, 매일 08시 전)

2026-11-23 사용자 요청으로 철강시세와 원/달러 환율은 **매일** 갱신한다. (2026-11-24부터 건설동향·방화문도 매일 — 위 «매일 아침 전체 갱신» 절)

- 고치는 항목: `stFx`(USD/KRW 줄: 값·등락·범위·추세·«YYYY.M.D 종가 · 설명»), `stAsOf`(오늘), 그리고 새 숫자가 확인된 철강 항목(`stPrice`·`stCard`·`stCheck`·`stRaw`·`stRawCard`·`stScrap`·`stScCard`·`stScGrade`·`stScNote`·`stDates`·`stVerify`·`stSummary`·`stFcast`). `asOf`·건설동향 항목은 건드리지 않는다.
- 원/달러: 전 영업일 서울 외환시장 종가(주간거래 15:30 종가)와 전일 대비 등락(«-3.0원 (당일)» 형식). 주말·휴일엔 마지막 영업일 값 유지.
- 카드 흐름(`stCard` 마지막 칸·`stRawCard` 마지막 칸)은 값이 바뀐 품목만 끝에 새 값을 붙이고 맨 앞 하나를 뺀다(점 개수 유지). 값이 그대로면 손대지 않는다.
- `stHistory` 는 숫자가 실제로 바뀐 날만 맨 앞에 `오늘|내용` 줄을 넣고 `hkeys.stHistory` 를 오늘로. 바뀐 게 없으면 `stHistory`·`hkeys` 그대로.
- `tag`: 오늘 날짜(YYYY-MM-DD). 이미 오늘 날짜로 시작하는 tag 가 있으면(목요일 주간 갱신 뒤 등) 끝 글자를 다음 영문 소문자로(`2026-11-26` → `2026-11-26b`).
- 바뀐 숫자가 하나도 없으면 커밋하지 않는다(환율이 그대로인 휴일 포함).
- 검사·커밋 순서는 위 «순서»와 같음. 커밋 메시지 «철강·환율 일일 갱신 YYYY-MM-DD — 주요 변동 한 줄».

### 매일 아침 갱신 — 방화문 뉴스·동향 (`fdNews`, 2026-11-23 추가)

- 지난 1~3일 방화문·건축자재·주택·건설경기 관련 보도(국토교통부 보도자료·고시·입법예고, 주택통계, 건산연, 건설경기실사지수, 철강·원가, PF·분양 등) 중 방화문 수요·원가에 영향 있는 것만 `fdNews` 맨 앞에 줄로 넣는다. 형식 `YYYY.MM|긍정·부정·중립|구분(4~6자)|요약 — 영향` (4칸 고정). 굵게는 `<b>…</b>` 만.
- 이미 있는 내용과 같은 사안이면 새 줄을 넣지 말고 그 줄을 최신 숫자로 고친다. 전체 15줄을 넘으면 가장 오래된 줄부터 뺀다(«규제» 줄은 1년 유지).
- 뉴스를 바꾼 날은 `fdNewsAsOf` 를 오늘(YYYY-MM-DD)로. 홈페이지 «방화문 시장 동향» 업데이트 일자가 이 값을 씀. 바꿀 뉴스가 없으면 그대로.
